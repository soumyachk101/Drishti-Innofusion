5. Soft vs hard state

PatternUsageRationale
Soft deleteLiveThreat.clearedUser action to dismiss; cleared threats hidden from list
Status fieldFinding.statusWorkflow: open → remediating → resolved/accepted
Auto-resolveFinding.auto_resolvedAgent removed a service; finding no longer applies
Time-bounded acceptanceFinding.accepted_untilRisk accepted for a window; auto-resumes monitoring after expiry
Demo labelLiveThreat.demo_labelSeparates demo from real threats; cleared on demo stop

6. UUIDs everywhere

All primary keys are 36-character UUID strings (not UUID columns). This ensures:

  • Postgres + SQLite compatibility: string PKs work identically on both backends
  • No migration conflicts: append-only schema changes (reconcile_columns)
  • No special types: standard VARCHAR, no UUID extension needed

8. Idempotency rules (ingest)

EntityIdempotency keyOn collision
Asset(org_id, ip)Update if found; keep operator-criticality; never downgrade
Service(asset_id, port, protocol)Replace (upsert)
Finding(asset_id, vulnerability_id)Replace (upsert); stale open findings auto-resolve
Connection(from, to, relation)Skip duplicates
Scan(org_id, source, started_at)New row per ingest call
NetworkDevice(org_id, mac) or (org_id, subnet, ip)Update timestamps; subnets only observed by that agent
